# Lumora v0.2.0 — status (2026-11-15; nothing has been run on a Mac yet)
1. Compiles: all 4 crates (~17.2k lines Rust, +7.1k since v0.1) pass `cargo check` + `cargo clippy --all-targets -D warnings` for aarch64-apple-darwin and x86_64-apple-darwin with 0 errors, 0 warnings; `cargo fmt --check` clean. Linking/running was not possible in the Linux sandbox; v0.1's main branch did pass real macOS CI.
2. Tests: 175 pass on Linux (lumora-core 171: v0.1's 76 + annotation paths/shapes/hit-testing/undo/editor FSM 70, i18n 8, OCR assembly 7, stitching 5, window-only picking 3, settings/action 2; lumora-ui tokens 3; app 1). +1 recorder test compiles for macOS only. Icon script self-checks its .icns.
3. Untested on hardware: everything AppKit/Vision/CoreImage — editor event routing, layer vs export alignment (text metrics, redaction on Retina), NSTextField editing + ⌘C/V without an Edit menu, NSColorPanel in an accessory app, OCR quality, toasts, stitching, plus all v0.1 flows.
4. Risks: (a) objc2 selector/ownership mistakes only show at runtime (new: editor views, CI filters, VNRecognizeTextRequest); (b) key events in non-activating panels / accessory-app windows; (c) shadow offsets in flipped export contexts may differ by 1 pt from the live view;
5. (d) Vision zh-Hant/ja accuracy depends on macOS version; (e) AVAssetWriter timing and SendBox serial-queue soundness (unchanged from v0.1); (f) ad-hoc signing resets Screen Recording permission each build.

Done: annotation editor (all 12 tools, palette + custom, 3 widths, undo/redo, select/move/resize/delete, ⌘C/⌘S/drag-out, springs), Capture Text ⌥⇧2, toast HUD + hotkey conflicts in Settings, en + zh-Hans (live switch), click-to-pick window mode, stitched multi-display area captures, app icon (.icns + Info.plist + bundle.sh). Partial: recordings spanning displays still clip to one display (TODO); editor annotations are flattened, not re-editable after closing; editors keep their language until reopened.
